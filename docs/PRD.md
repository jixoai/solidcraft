## 2. 产品摘要

### 2.1 一句话定义

SolidCraft 让人和 agent 使用同一套命令，创建、修改、验证和交付可编辑的参数化 CAD 模型；人在桌面或浏览器中始终能够看见结果、控制过程，并保留自己的设计。

### 2.2 核心价值

1. **可编辑，不止可视化**：产物保留草图、约束、参数和特征时间线，而非仅生成图片或网格。
2. **人机同权操作**：UI、CLI、MCP、浏览器 API 和 WebMCP 复用命令体系，避免维护第二套建模语义。
3. **本地可用、浏览器可达**：支持桌面工作流和无需安装的网页入口，核心建模不要求云端计算。
4. **结果可验证**：通过精确几何、时间线健康、参数修改和保存重开检查确认结果，不把“命令成功”当成“设计正确”。
5. **可靠且独立**：失败可解释、设计可恢复；遵守独立开发与开源许可边界。

### 2.3 产品成熟度声明

当前适用于简单零件及已有覆盖的组合建模场景，不应宣传为全面成熟的工业 CAD 替代品。复杂模型演示证明特定流程可完成，不证明任意布尔、圆角、曲面或装配都可靠。

## 3. 问题、用户与场景

### 3.1 需要解决的问题

| 问题 | 用户影响 | 产品回应 |
| --- | --- | --- |
| 绘制和约束零件需要大量重复操作 | 原型迭代慢，结构修改成本高 | 参数、表达式、时间线和重复特征 |
| agent 只能输出建模建议或不透明结果 | 无法核查，也难以继续编辑 | 真实命令执行、阶段检查、可编辑设计 |
| 浏览器长任务占用主线程 | 视图卡住，用户无法判断或停止 | Worker 计算、进度、取消和结果一致性 |
| 操作报成功但孔槽未切中或引用失效 | 交付错误结构 | 几何测量、目标实体约束、参数回归 |
| 模型只存在当前标签页 | 刷新、崩溃或关闭造成损失 | 保存、恢复、导出和重开验收 |
| 不同入口的命令行为不一致 | 脚本和 UI 无法互相接续 | 统一命令、参数定义和撤销语义 |

### 3.2 目标用户（建议）

| 用户 | 核心任务 | 最重要的成功标准 |
| --- | --- | --- |
| 个人创客、硬件原型设计者 | 外壳、支架、连接件和小型装置 | 改尺寸后仍有效，文件可用于后续制造流程 |
| 熟悉 CAD 的机械设计者 | 参数化零件、组件和初步装配检查 | 约束明确、引用稳定、结果可测量 |
| 教学和学习用户 | 理解草图、约束、特征和参数关系 | 过程可见、错误可理解、能够撤销 |
| agent 使用者 | 以自然语言委托外部 agent 建模和修改 | 真实执行、可中断、模型可接手 |
| 自动化开发者 | 批处理、验证、格式转换和集成 | 无对话框协议、可发现命令、结构化错误 |

首阶段优先服务创客、硬件原型和 agent 辅助建模。用户规模、行业占比和付费意愿尚无数据，不在本文假定。

### 3.3 代表性场景

- **参数化外壳**：建立带壁厚、接口、散热槽和安装柱的外壳，修改电路板尺寸后重建。
- **复杂产品造型**：建立包含外壳、屏幕、旋钮、电路板和支架的桌面仪器，展示装配和拆解。
- **agent 接续修改**：agent 检查已有模型，只改指定参数或部件；用户继续手动编辑。
- **浏览器长任务**：计算布尔或批次时仍可旋转视图；停止后不提交被取消的结果。
- **交付与恢复**：保存 `.sc`，关闭并重开，确认参数、时间线、实体和关键测量保留。

### 4.2 本工作区证据

- AERO 01 桌面监测仪由真实 `document.modelContext.executeTool` 调用构建，包含 95 个封闭实体、96 个时间线特征及 12 张零自由度草图。
- 装配和拆解保存文件已重开检查；宽度、深度和壁厚测试及关键解析体积检查有记录。
- 80 立方体同构建、交替三次的既有测量：同步调用总耗时中位数约 480.3 ms，Worker 约 634.6 ms；各次最大帧间隔的中位数由约 450 ms 降至约 33.4 ms。
- 上述结果说明该场景的响应改善，同时总耗时增加；不能外推为所有复杂模型都流畅或吞吐更高。
- 该阶段已有相关单元测试、真实 Chrome WebMCP、浏览器 API、离线、wasm 和部分静态检查记录，但当时未运行完整 `cargo xtask ci`，不能宣称发布门禁通过。2026-11-06 的 fork 同步、后续门禁失败与整合验证见 [fork 维护记录](fork-maintenance.md)。

本地证据位于 `target/webmcp-evidence/` 和 `target/live-webmcp-demo/`，通常不随仓库分发。进入发布验收时，必须记录构建标识、设备、脚本和可取得的报告；不可把本地链接或已有截图当成永久公开服务。

## 5. 产品目标与范围

### 5.1 本阶段目标（建议）

| 编号 | 目标 | 可观察结果 |
| --- | --- | --- |
| G-01 | 完成参数化建模闭环 | 新建设计到保存重开，无需丢弃参数或特征历史 |
| G-02 | 完成真实 agent 建模闭环 | 发现命令、分阶段执行、测量、修改、保存全部可追踪 |
| G-03 | 降低长计算期间界面阻塞 | 指定基准下视图持续刷新，用户能停止，旧结果不污染设计 |
| G-04 | 支持可展示的复杂多实体模型 | 完整仪器类模型及装配/拆解视图通过验收，而非仅堆叠基础体 |
| G-05 | 保持桌面与浏览器语义一致 | 同一支持命令的参数、错误和设计语义一致，宿主能力差异明确 |
| G-06 | 保证用户资产控制 | 不静默覆盖设计，不默认上传设计，保存和恢复状态可解释 |

### 5.2 优先级定义

- **P0**：本阶段主链路与安全发布门禁，缺失或回归阻止阶段验收。
- **P1**：提升复杂模型效率和可用性，不阻止受支持基本场景的闭环。
- **P2**：探索项，单独评审，不构成本阶段承诺。

这里的优先级是本 PRD 建议，不要求删除、隐藏或降级产品已经存在的功能。

### 5.3 非目标

- 不实现自有大模型、训练服务或必选云端 agent 平台；自然语言理解可以由外部 agent 提供。
- 不在本阶段交付完整 CAM、有限元分析、完整工程图或全面工业认证能力。
- 不承诺跨标签页协同编辑、跨源 WebMCP 暴露、云账户、云同步或多人权限体系已可用。
- 不承诺任意来源 CAD 文件无损转换或原生历史恢复。
- 不以改写现有内核性能为本阶段工作；遵循内核暂停与迁移策略，问题按现有渠道记录。
- 不实现通过屏幕图片生成的伪 CAD、网格替代精确实体决策或商业 CAD 数据抓取。
- 不制定收费、订阅和商业化指标；这些需要独立产品决策。

## 6. 核心用户旅程

### 6.1 手动建模

进入应用 → 新建独立文档 → 创建命名参数 → 草图与约束 → 实体特征 → 测量 → 修改参数 → 保存 → 重开 → 导出受支持格式。

每一步应反馈当前对象、可用操作和错误。取消草图、撤销特征或保存失败不能造成无法解释的状态。

### 6.2 agent 建模

连接正确页面/会话 → 检查已有设计和工具 → 确认修改范围 → 给出阶段方案 → 查询命令定义 → 执行几何批次 → 单独设置外观 → 测量和展示 → 参数测试 → 保存与重开 → 交付设计及记录。

涉及已有文档清空、覆盖、破坏性变更或对外发送设计时，必须有明确用户授权。新建独立模型且不影响已有资产时，不要求每个几何命令都弹出确认框。

### 6.3 人与 agent 交替编辑

agent 计算期间用户导航或编辑 → 导航不中断正常路径 → 用户编辑优先 → agent 结果检查文档和版本 → 必要时基于新版本重试 → 超出重试或文档切换时报告拒绝。

不是无约束的并行写入。多个 agent 对同一文档的同时修改不属于本阶段承诺，应串行协调。

## 7. 功能需求

### 7.1 文档、草图与参数

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| DOC-01 | P0 | 新建、打开、保存独立设计，明确当前文档与修改状态 | 新建不覆盖旧文档；写入失败不标记已保存；重开保留模型和历史 |
| DOC-02 | P0 | 提供撤销、重做、草图取消及失败恢复 | 支持场景恢复预期状态；agent 与 UI 共用历史，不创建独立不可撤销修改 |
| DOC-03 | P0 | 参数具有名称、表达式、单位和依赖错误 | 单位非法、循环或删除被引用参数返回可解释错误；成功修改触发重建 |
| DOC-04 | P0 | 草图可创建、求解并报告自由度 | 标准受支持案例达到 DOF 0；冲突明确报告，不静默删除约束 |
| DOC-05 | P1 | 展示参数说明、建议范围、收藏与配置 | 用户能找到关键尺寸；推荐范围与实际强制约束区分；越界不伪称已被拦截 |
| DOC-06 | P0 | 保存与恢复遵守平台存储语义 | 桌面安全写入；浏览器权限/配额失败明确报告；恢复流程不静默替换用户文件 |

### 7.2 实体、组件与验证

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| CAD-01 | P0 | 覆盖主链路所需拉伸、孔槽、壳、阵列及组合操作 | 选定标准零件完成；每项受支持操作有可重复案例，不以工具数量代替验证 |
| CAD-02 | P0 | 切除和合并具有明确目标实体 | 相邻未选实体保持不变；未切中通过测量发现并不能通过模型验收 |
| CAD-03 | P0 | 保留参数化时间线和稳定引用 | 范围内尺寸修改后预期引用仍有效；失败定位到相关特征 |
| CAD-04 | P0 | 返回精确几何测量和时间线健康信息 | 可读取体积、包围盒、封闭状态、草图自由度及特征错误/警告 |
| CAD-05 | P1 | 支持有意义的部件组织和装配/拆解展示 | 各零件名称唯一可辨；拆解不改变零件体积；命名视图可恢复 |
| CAD-06 | P1 | 提供已覆盖的装配检查和运动能力 | 按支持矩阵验收干涉、质量或关节案例；不把分离摆放视为完整装配约束 |

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |

### 7.4 命令、MCP 与 WebMCP

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| AG-01 | P0 | 各入口复用命令注册表与语义 | 相同命令的参数、设计结果及错误一致；宿主不支持的能力明确失败 |
| AG-02 | P0 | 命令可发现并可查询参数定义 | agent 查询后可构造合法请求；未知参数和类型错误不能偷偷忽略 |
| AG-03 | P0 | 当前五个 WebMCP 工具具有真实注册与失败信封 | 真实浏览器调用通过；无 WebMCP 或部分注册失败不使 CAD 应用崩溃 |
| AG-04 | P0 | 支持事务批处理与诚实的部分失败状态 | `rollback: true` 恢复设计；失败报告索引、原因、完成情况及是否回滚；文件副作用不伪称可撤销 |
| AG-05 | P0 | 支持停止与原生调用取消 | 被取消结果不提交；取消监听清理；后续请求可继续 |
| AG-06 | P0 | 处理输入、请求队列和消息大小限制 | 超限拒绝且设计不变；失败原因保留；下一合法请求可成功 |
| AG-07 | P0 | agent 能检查并接续用户模型 | 操作前读取当前文档；不默认清空；修改后用户能正常撤销和继续编辑 |
| AG-08 | P1 | 建模有可导出的过程记录 | 记录命令、参数、结果、失败、阶段和测量；保存前排除 token 等敏感信息 |
| AG-09 | P1 | 面向其他 agent 提供可复用说明和示例 | 有真实工具、命令发现、分批、测量、保存及错误恢复示例；不靠伪造 API |

| 工具 | 输入 | 用途 |
| --- | --- | --- |
| `solidcraft_list_commands` | 按注册 schema | 获取命令目录；避免反复展开完整目录 |
| `solidcraft_describe_command` | `{command}` | 查询命令定义，不猜参数 |
| `solidcraft_execute` | `{command, params?}` | 无交互式对话框执行单命令 |
| `solidcraft_batch` | `{commands, rollback?}` | 顺序批处理及设计回滚 |
| `solidcraft_inspect` | `{measure?}` | 检查当前文档，可选测量 |

成功返回 `{ok: true, result}`；失败返回 `{ok: false, error}`。失败 batch 保留 `result` 中的失败与回滚信息。WebMCP 自身异常或取消仍可能以 Promise rejection 返回，调用方必须同时处理。

输入 schema 与输出 schema 是统一命令目标；现有未转换命令仍存在，不宣称全部已完成。新增/改动命令遵守项目 ratchet 和 schema 规范。

### 7.5 浏览器计算、文件和离线

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| WEB-01 | P0 | 长几何计算在已启用的 Worker 路径执行 | 通过 runtime 和真实基准确认；不能仅根据偏好默认值推断使用 Worker |
| WEB-02 | P0 | 复用 wasm、会话与有效计算结果 | 连续请求复用；UI 应用结果不再完整重放建模或重建同一显示结果 |
| WEB-03 | P0 | 计算提交检查文档和版本 | 用户编辑优先；当前有限重试后明确失败；文档切换拒绝旧事务 |
| WEB-04 | P0 | 传输失败后保留设计并恢复请求能力 | 128 MiB 超限或注入失败不提交 staged 模型；下一请求能重新建立 Worker |
| WEB-05 | P0 | 诚实区分 Worker 与宿主路径 | 文件、外观等混合 batch 可能回退宿主；记录可识别，不宣称所有操作都离线程 |
| WEB-06 | P0 | 浏览器文件能力遵守 VFS、OPFS 与权限 | 不把虚拟路径当本机任意路径；下载、导入、保存失败返回正确状态 |
| WEB-07 | P1 | 已缓存应用的离线及更新流程可验证 | 在明确缓存前提下离线打开和保存；更新不破坏设计；首次离线访问不承诺成功 |
| WEB-08 | P2 | 演进至 broker、分层存储和可选云委派 | 单独设计和验收；兼容旧文件与恢复，不能以当前 Worker 代替完成声明 |

## 8. 非功能需求

### 8.1 可靠性与几何正确性

- 输入视为不可信；生产 Rust 遵守不使用未批准 `unsafe`、`unwrap`、`expect`、panic 等规则，错误走 `Result`。
- 原生 B-rep 和精确几何用于模型决策，显示网格仅用于允许的显示、预览、导出和网格体场景。
- 命令失败、Worker 失败、取消、过期结果和保存失败都不得静默破坏用户设计。
- 简单解析案例的容差依据建模校验规范及案例尺度设置，不统一使用任意固定小数位，也不从商业 CAD 提取参考值。
- 标准流程必须验证名义参数与范围内变更；范围说明不能替代实际重建测试。
- 已知失败保留清晰记录，不通过放宽 golden、删除检查或伪造结果掩盖。

### 8.2 性能目标与测量口径（建议，未获批准）

以下是待验证目标，不是当前产品保证。发布前锁定参考设备、操作系统、浏览器、GPU、构建和显示质量，分别报告冷/热状态；未锁定设备前不能判定跨设备达标。

| ID | 场景 | 建议验收目标 | 边界 |
| --- | --- | --- | --- |
| PERF-01 | 支持浏览器、热缓存、空文档启动 | 5 次启动的中位数不超过 8 秒 | 冷下载单列包大小、网络和时间；不混入此指标 |
| PERF-02 | 80 基础实体纯几何批次 | 5 次运行中，各次最大帧间隔的中位数不超过 50 ms | 活跃标签页，同构建交替对照；完整范围同时报告 |
| PERF-03 | 仪器类复杂模型旋转与长计算 | 连续导航时帧间隔 P95 不超过 50 ms；超过 100 ms 的间隔逐项归因 | 计算、结果解码/应用、GPU 上传、宿主操作分开记录；最大值不得隐藏 |
| PERF-04 | 已开始的 Worker 计算取消 | 输入停止到取消状态的 P95 不超过 500 ms | 目标限 Worker 路径；未能取消的宿主操作单列，不扩大承诺 |
| PERF-05 | 相同输入的结果一致性 | 同步与 Worker 的实体、参数和关键测量在既定容差内一致 | 提升响应不能跳过必要计算或改变几何语义 |
| PERF-06 | 生命周期与资源稳定性 | 指定 20 轮重复开关/建模/取消后无遗留 pending 和监听；Worker 数量符合会话生命周期 | 内存需区分活模型、缓存和可回收对象；预算基于测量另行批准 |

统一报告：命令数、实体数、总耗时、Worker 计算耗时、主线程结果应用耗时、帧间隔分布、请求/响应大小、峰值内存及失败记录。不得用总耗时缩短替代响应指标，也不得将少数演示视为受控基准。

### 8.3 现有容量与兼容约束

| 项目 | 当前协议限制/边界 |
| --- | --- |
| JSON 单请求 | 最多 16 MiB |
| pending 请求数量 | 最多 256 |
| pending 参数总量 | 最多 32 MiB |
| batch 步数 | 1–10,000；产品建议按结构阶段适度拆分，不以最大值作推荐值 |
| 二进制 Worker 消息 | 最多 128 MiB；这是传输上限，不是总体内存预算 |
| WebMCP | 依赖支持的浏览器及功能启用；无支持时普通 CAD 与浏览器 API 可继续工作 |
| 页面状态 | 活跃标签页参与验收；隐藏/挂起可能延迟请求，刷新终止当前会话工作 |
| 嵌入与跨源 | 当前同源权限策略；跨源 `allow="tools"` 单独设置不能授予本集成未配置的暴露能力 |
| Worker 部署 | 当前 Worker 路径要求 CSP 允许相应 worker 源；不能通过放宽整体安全策略图省事 |
| 原生/浏览器 | 核心命令一致；系统文件、剪贴板、窗口及格式能力按宿主支持区分 |

改变限制或默认值须单独评审；旧同步行为继续由 `agent_off_thread=false` 保留。现有用户保存的偏好不能被静默覆盖。

### 8.4 安全、隐私与独立性

- 默认不向云端上传设计、命令参数或原始几何；外部 agent 服务的数据流由使用者明确知晓。
- 浏览器 WebMCP 不提供任意本机文件访问或新网络监听；桌面控制通道保留本地 token 与访问规则。
- 导入设计中的名称、文本和工具返回数据视为不可信内容，不作为 agent 的新指令或权限授权。
- 导出/保存和其他有副作用的命令应诚实声明；回滚设计不能撤回已经写出的文件。
- 设计、日志和崩溃材料不自动公开；提交诊断前提供授权及敏感信息清理。
- 不读、复制或链接禁用许可的代码，不抓取商业 CAD 的代码、图标、文本、模板和参考数据。
- 所有新增资产遵守原创或开放许可及 attribution 规则；应用代码保持 Rust 与 wasm 可构建。

## 9. 标准验收场景

### AC-01：基础参数化零件

建立带孔、倒角或圆角的支架，至少三个关键参数；草图 DOF 0，体积及包围盒符合解析参考。修改尺寸后重建成功，撤销/重做保留正确状态，保存并重开。

### AC-02：复杂仪器模型

包含圆角薄壁机壳、可拆前面板、屏幕、旋钮/按钮、真实散热槽、安装柱、PCB、紧固件和支架。建议规模 50–150 个有意义的实体，不把数量视为质量门槛。

要求所有预期实体封闭，草图 DOF 0，时间线无未解释错误/警告；三个关键参数各测试至少两个范围内不同值并恢复。主要零件体积和布局检查通过，装配与拆解体积一致、位移可验证。

### AC-03：真实 WebMCP

在独立的真实浏览器会话中发现五工具，查询 schema，创建新文档并分阶段建模。包括成功单命令、batch、非法输入、部分失败、`rollback: true`、取消及下一请求恢复。无 WebMCP 和部分注册失败时普通应用仍可用。

### AC-04：人机接续与过期结果

长计算期间导航、用户编辑和切换文档；检查导航仍走正常路径，结果不覆盖更新版本或错误文档。验证有限重试、拒绝原因、撤销历史和选择/视图状态。

### AC-05：显示缓冲与传输故障

使用可重复的超限或故障注入，而非依赖偶然卡顿。确认当前设计未改变、失败有具体原因、pending 清理和下一请求成功。记录极薄圆片等显示缓存膨胀案例，不规定某个厚度是通用安全阈值。

### AC-06：保存、离线与重开

保存到新文件，检查实际写入及版本；关闭并重开后检查实体数、参数、时间线和关键测量。浏览器覆盖权限拒绝/配额失败与已缓存离线；导出一个受支持格式并验证实际下载和合理重开能力。格式转换不假定保留设计历史。

### AC-07：交付与证据

提供 `.sc` 设计、参数表、命令记录、检查报告及自己捕获的装配/内部结构截图。模型链接需实际访问与重开验证；本地链接标明服务有效期，不能称为在线发布。可见浏览器保留最终模型且用户可继续操作。

## 10. 成功指标与数据策略

### 10.1 核心指标

**建议北极星指标：经验证的参数化设计完成数。** 一次完成必须包含有效模型、参数修改检查和可重开的保存产物；只生成图片、只执行成功命令或重复打开同一设计不计新完成。

该定义先用于人工验收和自愿测试；不是已部署的自动遥测系统。

| 指标 | 定义 | 目标/状态 |
| --- | --- | --- |
| 标准任务通过率 | 通过全部验收步骤的指定案例 / 总指定案例 | P0 受支持案例 100%；已知不支持另列，不临时移出分母 |
| 设计保存重开一致率 | 重开测量与保存前一致的案例 / 保存验收案例 | P0 案例 100% |
| 取消与错误恢复通过率 | 故障后设计未损坏且下次请求成功的案例 / 故障案例 | P0 案例 100% |
| 参数范围稳定率 | 通过重建和测量的测试点 / 预先指定测试点 | P0 场景 100%，复杂扩展按支持矩阵报告 |
| agent 闭环成功率 | 无人工几何修补即可验收的标准 agent 任务 / 标准任务 | 先建立基线，再批准扩展任务目标；不虚构当前比例 |
| 交互响应与完成耗时 | 第 8.2 节定义的性能分布 | 同时报告，不只取有利指标 |
| 首次有效设计用时 | 用户开始到首个验收设计的时间 | 通过自愿用户测试建立基线，暂不承诺数值 |

### 10.2 数据获取边界

优先使用本地测试、可导出诊断和自愿研究。任何新增运行时遥测需单独评审默认值、告知、退出和保留周期；不收集原始设计、几何或完整 agent 对话作为默认指标数据。

## 11. 技术与交付约束

本节限定实现边界，不要求采用尚未落地的目标架构：

| 层 | 责任 |
| --- | --- |
| `geom` | 几何基础 |
| `sketch` / `kernel` / `render` / `dynamics` | 求解、内核边界、显示和动力学 |
| `doc` | 参数、设计、特征时间线和求值 |
| `io` | 格式、导入导出和安全写入 |
| `engine` | 会话及统一命令 |
| `ui-egui` / `gpu` / `mcp` | UI、显示计算和 agent 接口 |
| apps | 桌面、CLI、浏览器宿主 |

- 只有既定内核层可使用 truck；新内核案例遵循 SolidCore 归属与现有暂停/迁移规则。
- WebMCP 是既有控制语义的浏览器适配，不引入第二套 feature engine 或命令目录。
- Worker 模型传输是暂态协议，不等于修改 `.sc` 持久化格式；真正格式变更遵循 pending 文件及迁移规则。
- 新命令有 schema、错误和测试；新运行时文本、资源和默认值遵循仓库流程。
- 应用代码 Rust-only；浏览器必要 glue 保持最小，不将本地建模辅助脚本变成应用依赖。

## 12. 建议阶段与退出条件

没有承诺日期或人力估算。由负责人根据能力矩阵、依赖和实际验证结果排期；发布节奏沿用现有项目规则。

| 阶段 | 主要交付 | 退出条件 |
| --- | --- | --- |
| M0：基线确认 | 受支持案例、浏览器/设备矩阵、现有实现与发布差异、问题清单 | 所有需求有状态与负责角色；量化目标和非目标经评审 |
| M1：可靠建模闭环 | 文档、参数、草图、实体、测量、保存重开 | AC-01、AC-06 及相关 P0 需求通过 |
| M2：真实 agent 与响应 | WebMCP、Worker、取消、回滚、人机接续、失败恢复 | AC-03/04/05 和批准的性能目标通过；不损失原同步行为 |
| M3：复杂可见模型 | 标准仪器案例、部件组织、参数范围、装配/拆解、记录 | AC-02/07 通过；可由另一 agent 在独立文档复现 |
| M4：发布准备 | 文档、兼容声明、诊断、完整门禁和可取得证据 | 批准范围内 P0 全部通过；完整 CI 结果有效，无未解释阻塞问题 |

某些阶段内容已经本地验证，不要求重复从零开发，但进入退出条件必须重新确认版本和证据。

### 发布门禁

- 每次提交前按项目规定运行 `cargo xtask ci`，不能用本 PRD 中的本地记录替代。
- 真实浏览器覆盖 WebMCP、浏览器 API、离线与更新、取消、失败恢复及保存重开。
- 遵守 licences、assets、icons、lists、layers、ui-containers、mesh-decisions 和 wasm 检查。
- 可观察变更有本人捕获的截图或录屏；回归测试放入现有区域测试文件。
- 默认行为变化保留旧行为偏好，并按贡献流程明确声明。

## 13. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 几何操作覆盖不完整 | 复杂模型无法完成或尺寸修改失效 | 明确支持矩阵、解析检查和替代结构；问题遵循内核归属 |
| 极薄实体显示缓存膨胀 | 大消息、内存压力、传输失败 | 记录精确复现、合理结构、传输上限和失败恢复；不隐瞒失败 |
| Worker 响应改善但总耗时增加 | 误判性能或用户等待过长 | 分开测量交互与总耗时、热/冷状态及主要开销 |
| 混合 batch 回退宿主 | agent 认为离线程但界面卡顿 | 文档与诊断明确，几何/外观/文件分批，测量宿主路径 |
| 浏览器功能、CSP 或存储差异 | WebMCP、Worker 或保存不可用 | 能力检测、兼容说明、可解释失败和受支持降级路径 |
| 并行编辑或标签页挂起 | 过期提交、延迟和用户困惑 | 文档版本检查、有限重试、明确状态，不承诺并行写入 |
| agent 错误目标或提示注入 | 误删设计、数据泄露 | 先检查模型、唯一命名、明确授权、不可信内容与最小权限 |
| 路线图与功能分支混淆 | 对外宣称未发布能力 | 分状态标记，发布前复核，不用 issue 计数证明成熟度 |
| 演示被视为工程认证 | 使用不当和安全风险 | 明确造型/结构示意边界及现有免责声明 |
